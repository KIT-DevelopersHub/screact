# Screact for iOS

Native SwiftUI port of the Screact Android app (`android/`). The phone runs on-device hand and
ArUco-marker detection and streams only coordinates to the desktop server over WebSocket — it is a
drop-in client for the existing PC app (`desktop/`). Nothing in `android/` or `desktop/` was changed.

- Bundle ID: `com.nxtend.team35.yubiboard` (matches Android)
- Display name: **Screact**
- Deployment target: iOS 15.0
- Camera: rear (matches Android's `DEFAULT_BACK_CAMERA`)

## Architecture (module ↔ Android parity)

| iOS (`Screact/`) | Android source | Notes |
|---|---|---|
| `Protocol/Messages.swift`, `ProtocolCodec.swift` | `protocol/Messages.kt`, `ProtocolCodec.kt` | camelCase JSON, byte-compatible with desktop |
| `Network/YubiBoardWebSocketClient.swift`, `ConnectionModels.swift` | `network/*` | `URLSessionWebSocketTask`, no compression |
| `Vision/HandLandmarkerProcessor.swift` | `vision/HandLandmarkerProcessor.kt` | MediaPipe Tasks Vision, 21 landmarks |
| `Vision/ArucoBridge.{h,mm}`, `ArucoMarkerProcessor.swift` | `vision/ArucoMarkerProcessor.kt` | OpenCV ArUco `DICT_4X4_50`, IDs 10/11/12/13 |
| `Vision/MarkerStabilityTracker.swift`, `TrackingStateMachine.swift` | same names | pure logic, unit-tested |
| `Camera/CameraSession.swift`, `CameraProfile.swift` | `camera/*` | AVFoundation, 720p→540p→480p fallback |
| `Settings/AppSettings.swift`, `TrustedConnectionStore.swift` | `settings/*` | UserDefaults + Keychain (≈ Android Keystore) |
| `Diagnostics/AppDiagnostics.swift` | `diagnostics/AppDiagnostics.kt` | debug-gated telemetry |
| `UI/ProductionScreen.swift`, `ProductionModels.swift` | `ui/*` | SwiftUI port of the character UI + state machine |
| `ViewModel/MainViewModel.swift` | `MainViewModel.kt` + `MainActivity.kt` wiring | capture pipeline orchestration |

## Build

The project is generated by [XcodeGen](https://github.com/yonsm/XcodeGen) from `project.yml`.
`Screact.xcodeproj` is committed so it builds without any tooling. It compiles **without pods**:
MediaPipe and OpenCV are guarded by `#if canImport(...)` / `__has_include(...)`, so hand/marker
detection is stubbed until the dependencies are installed.

Vision dependencies (two different channels):
- **MediaPipeTasksVision** — hand landmarks — via **CocoaPods** (`Podfile`).
- **OpenCV 4.9** — ArUco `DICT_4X4_50` detector — via **Swift Package** (`project.yml`, from
  `github.com/yeatse/opencv-spm`). The `OpenCV` CocoaPod stops at 4.3.0 and lacks the
  `cv::aruco::ArucoDetector` API OpenCV 4.7+ exposes in `objdetect`, so it can't be used here.

### Pure build + tests (no pods, works out of the box)

```sh
cd ios
xcodebuild -project Screact.xcodeproj -scheme Screact \
  -sdk iphonesimulator -destination 'platform=iOS Simulator,name=iPhone 17' \
  build CODE_SIGNING_ALLOWED=NO
# unit tests (ProtocolCodec round-trips, stability tracker, tracking state machine, calibration reducer)
xcodebuild -project Screact.xcodeproj -scheme Screact \
  -sdk iphonesimulator -destination 'platform=iOS Simulator,name=iPhone 17' \
  test CODE_SIGNING_ALLOWED=NO
```

### Full app with vision (requires CocoaPods)

```sh
cd ios
xcodegen generate            # regenerate the project + resolve the OpenCV Swift Package
pod install                  # links MediaPipeTasksVision, creates Screact.xcworkspace
open Screact.xcworkspace     # build & run from the WORKSPACE from here on
```

`xcodegen generate` resolves the OpenCV Swift Package (opencv2.xcframework, ~200 MB download on
first run); `pod install` links MediaPipe. Both are needed for hand + marker detection.

Running on a physical device additionally needs a signing team (set `DEVELOPMENT_TEAM` /
select a team in Xcode → Signing & Capabilities). Camera does not work in the Simulator, so
end-to-end hand/marker capture must be tested on a device.

## Protocol compatibility

Wire format is identical to Android (verified by `ScreactTests/ProtocolCodecTests`):
`ws://<host>:<port>/ws/v1/input`, default port **8765**, cleartext (ATS `NSAllowsArbitraryLoads`),
6-digit pairing code, camelCase JSON, nil fields omitted. `URLSessionWebSocketTask` does not
negotiate permessage-deflate, matching the server's compression-off requirement. The app therefore
talks to the current desktop server unchanged.

## Model / assets

`Resources/hand_landmarker.task` is the same MediaPipe model bundled by Android (see
`Resources/MODEL_ATTRIBUTION.md`). The character and watercolor art are reused from the Android
`drawable-nodpi` assets via `Assets.xcassets`.
