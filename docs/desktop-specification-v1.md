Desktop アプリは、Android から受け取った位置合わせ結果と手指ランドマークを、PC画面上のポインター、描画、操作イベントへ変換する処理主体です。Flutter/Dart の共通層に、macOS/Windows のネイティブウィンドウ・入力連携を組み合わせます。

## システム概要

### アーキテクチャ

```mermaid
flowchart LR
    Discovery["UDP Discovery"] --> Server["WebSocket Input Server"]
    Server --> Calibration["Calibration / Homography"]
    Server --> Engine["Interaction Engine"]
    Engine --> Filter["One-Euro Filter"]
    Filter --> Gesture["Gesture Recognizer"]
    Gesture --> Overlay["Overlay / Ink"]
    Gesture --> Bridge["Desktop Bridge"]
```

### 主要機能

| 領域 | 実装内容 |
| --- | --- |
| 接続 | UDP `8766` で接続情報を広告し、WebSocket `8765/ws/v1/input` を待ち受ける。 |
| 認証 | 初回は6桁 `pairingToken`、再接続は `resumeToken` を用いる。詳細は [通信仕様書 v1](./protocol-specification-v1.md)。 |
| 座標処理 | 4点の ArUco 結果から Homography を計算し、手の座標を画面座標へ変換する。 |
| 操作判定 | ポインター、ピンチクリック、ドラッグ、描画、グー消しゴム、グッドサイン・スクロールをイベント化する。 |
| 描画 | 色選択・骨格表示を持つ操作画面と、透明・クリック透過のオーバーレイを提供する。 |

## 接続と処理フロー

1. Desktop が接続情報と6桁コードを UDP で広告する。
2. Android が WebSocket 接続し、`hello` / `hello_ack` でセッションを確立する。
3. Desktop が配置確認後に ArUco マーカーを表示し、Android の4点結果から変換行列を作る。
4. `hand_frame` を受信し、最新フレームを優先して平滑化・座標変換・ジェスチャー判定を行う。
5. 判定結果をオーバーレイ描画または OS 入力へ反映する。

メッセージのフィールドとエラー契約は、必ず [通信仕様書 v1](./protocol-specification-v1.md) を参照する。

## 操作とオーバーレイ

位置合わせ完了後は透明・最前面・クリック透過のオーバーレイへ移行します。macOS ではメニューバーまたは `⌘⇧O`、Windows では `Ctrl+Shift+O` で解除でき、切断時にも安全に解除します。

### ジェスチャーとイベント

ジェスチャーの判定と操作イベントへの変換は `desktop/lib/core/gesture_recognizer.dart` と `desktop/lib/core/interaction_engine.dart` が行います。指同士の接触は、手首から人差し指の付け根までの距離（手の大きさ）に対する比で判定するため、カメラからの距離に左右されにくくなっています。

| ジェスチャー | 判定条件 | Desktop のイベント | OS 入力 |
| --- | --- | --- | --- |
| 人差し指の移動 | 下のどのジェスチャーにも当たらないとき | `pointerMove`。位置は人差し指の先端 | あり（カーソル移動） |
| ピンチ（親指と人差し指をくっつける） | 親指の先端と人差し指の先端の距離が、しきい値より近い | `pressDown` → `pressMove` → `pressUp`。押してから 260 ms 以内、移動量が画面の 0.02 以内で離すと、`pressUp` の前に `click` も出す | あり（左ボタンの押下・ドラッグ・解放）。`click` は OS には送らない（押下と解放でクリックが成立するため） |
| 描画（人差し指と中指をくっつける） | 人差し指の先端と中指の先端の距離が、しきい値より近い。グーとグッドサインのときは除く | `drawDown` → `drawMove` → `drawUp`。筆点は人差し指の先端 | なし（オーバーレイにだけ描く） |
| 消しゴム（グー） | 人差し指〜小指の 4 本をすべて折る。グッドサインのときは除く | `eraseDown` → `eraseMove` → `eraseUp`。消す位置は人差し指の先端と中指の先端の中間点 | なし（オーバーレイのインクだけを消す） |
| スクロール（グッドサイン） | 親指を伸ばし、人差し指〜小指の 4 本を折る。ピンチ中は除く | `scroll`。親指の向き（親指の付け根から先端へ向かう向きを画面座標に写したもの）のうち、縦と横の大きいほうへ、1 フレームごとに画面の 0.03 ずつ送る。上・下・左・右の 4 方向で、手の移動量は使わない。スクロール中はポインターを動かさない | あり（縦・横のホイール。量は画面サイズに応じてネイティブ側で換算する） |

- 接触の判定にはヒステリシスがあります。認識感度が既定の 0.5 のとき、ピンチは手の大きさの 0.40 倍より近づくと ON、0.60 倍より離れると OFF、描画は 0.35 倍で ON、0.55 倍で OFF です。認識感度を上げると、指が離れていても接触とみなします。
- グーは、伸びている指が 0 本で ON、2 本以上で OFF になります。1 本のときは直前の状態を保ちます。
- 親指は、先端と付け根の距離が手の大きさの 0.8 倍を超えると「伸びている」とみなします。

### 判定の優先順位

1 つの手で同時に出すジェスチャーは 1 つだけです。毎フレーム、次の順に判定し、最初に当たったものを採ります。

1. 消しゴム（グー。ただしグッドサインは除く）
2. スクロール（グッドサイン）
3. 描画（人差し指と中指の接触）
4. クリック / ドラッグ（ピンチ）
5. ポインター移動

上位のジェスチャーが始まると、続いていた下位の描画・押下は終了イベント（`drawUp`・`pressUp`）で閉じます。このとき `click` は出しません。グッドサインは 4 本の指を折るためグーと描画の条件も満たしやすいので、消しゴムと描画の判定から除いています。

### ジェスチャーの個別 OFF

設定画面で、クリック、ペン（描画）、消しゴム、スクロールをそれぞれ OFF にできます（既定はすべて ON）。OFF にしたジェスチャーは認識せず、その手は優先順位の次の判定へ回します。ほかに当たるジェスチャーが無ければ、ポインター移動として扱います。たとえばクリックを OFF にすると、ピンチしてもポインターが動くだけです。

### 画面の外へ出たとき

人差し指の先端が画面（位置合わせした範囲）の外へ出ると、続いていた描画・消しゴム・押下を閉じてから `pointerExit` を 1 回出し、カーソルだけを隠します。検出中の骨格表示は残します。

- 画面の中へ戻っても、2 フレーム続けて中にあるまでは操作を再開しません。
- ピンチしたまま外へ出た場合は、一度ピンチを離すまで押下を始めません（戻った瞬間の誤クリックを防ぐため）。
- 手を見失ったときやフレームが不正なときは、`release` で押下・描画・消しゴムをすべて解除します。
