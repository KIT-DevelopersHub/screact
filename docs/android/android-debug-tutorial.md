# YubiBoard Android実機デバッグ・チュートリアル

この資料は、デスクトップアプリが未実装でも、Android実機とWindows PCだけでYubiBoard Androidアプリの主要機能を順番に確認するための手順書です。

最初はUSB接続で通信経路を固定し、次の順番で確認します。

1. PCとAndroid実機がADBでつながる
2. アプリが起動してカメラ映像が表示される
3. 手の21点ランドマークが検出される
4. モックPCへWebSocket接続できる
5. 手のデータと位置合わせマーカーがPCへ届く
6. 通信断から自動復帰できる
7. 長時間動作でクラッシュ、発熱、メモリ増加がない

## 1. 用意するもの

- Windows PC
- Android 7.0（API 24）以上の実機
- データ通信対応USBケーブル
- Android StudioとAndroid SDK
- このリポジトリ
- 手を映せる明るい場所

コマンドは、特記がなければリポジトリルートでPowerShellから実行します。

```text
C:\Users\...\2026-Team-35>
```

Android Studioでは`android/`ディレクトリをプロジェクトとして開きます。

## 2. Android端末を準備する

端末の「設定」で開発者向けオプションを有効にし、次を確認します。名称はメーカーやOSバージョンによって多少異なります。

1. 「端末情報」を開く。
2. 「ビルド番号」または「OSバージョン」を7回程度タップする。
3. 開発者向けオプションを開く。
4. 「USBデバッグ」を有効にする。
5. Xiaomi端末では「USB経由のインストール」も有効にする。
6. USBでPCへ接続し、端末の「このPCからのUSBデバッグを許可する」を許可する。

デバッグ中は端末をロック解除したままにしてください。APK導入時に確認画面が出た場合は、端末側で「インストール」または「許可」を押します。

## 3. 最初の環境診断

```powershell
.\android\tools\android-debug.ps1 doctor
```

成功例です。

```text
adb: C:\Users\...\Android\Sdk\platform-tools\adb.exe
sdkRoot: C:\Users\...\Android\Sdk
serial: 2bd82477
manufacturer: Xiaomi
model: ...
android: 15
sdk: 35
resolution: Physical size: 1080x2392
packageInstalled: True
```

ここでは次を確認します。

- `serial`が表示される
- 端末が`device`状態になっている
- メーカー、機種、Androidバージョンが実機と一致する
- `adb`とAndroid SDKの場所が検出されている

### `adb`コマンドが見つからない場合

`android-debug.ps1`はAndroid SDK内の`adb.exe`を自動検出するため、通常は`adb`をPATHへ追加する必要がありません。以後も直接`adb`を実行せず、原則としてこのスクリプトを使ってください。

どうしても直接確認する場合は、`doctor`に表示されたフルパスを使います。

```powershell
& 'C:\Users\ユーザー名\AppData\Local\Android\Sdk\platform-tools\adb.exe' devices
```

`unauthorized`と表示された場合はUSBケーブルを接続し直し、端末に表示されるUSBデバッグ確認を許可します。

## 4. ビルドとインストール

まずPC上のテスト、Lint、debug APK、実機テストAPKをまとめてビルドします。

```powershell
.\android\tools\android-debug.ps1 build
```

最後に`BUILD SUCCESSFUL`と表示されることを確認します。次にアプリを実機へ導入します。

```powershell
.\android\tools\android-debug.ps1 install
```

カメラ権限もコマンドから付与する場合は次を使えます。ただし、権限要求画面自体を確認するときは指定しません。

```powershell
.\android\tools\android-debug.ps1 install -GrantCamera
```

アプリの保存設定を消して初回起動から確認したい場合だけ、`-ResetAppData`を付けます。この指定では保存済みIP、ポート、動作モードなども消えます。

```powershell
.\android\tools\android-debug.ps1 install -ResetAppData
```

## 5. アプリUIの基本確認

アプリを端末から開くか、次で起動します。

```powershell
.\android\tools\android-debug.ps1 start
```

初回は「カメラを許可」を押し、Androidの権限確認を許可します。

画面には次が表示されます。

- 上部: カメラ状態、PC接続状態、撮影モード
- 中央: 背面カメラ映像と手またはマーカーの重畳表示
- 下部: PC接続カード
- 接続カード上部: 「設定」と、デバッグモード時の「診断」
- 接続前: ホスト、ポート、6桁コード、「PCへ接続」
- 接続中: 接続先、「接続を切断」
- 常時: 「位置合わせを開始」または「手の追跡へ戻る」

「PCへ接続」ボタンは、位置合わせを行う前から接続カード内に表示されます。見えない場合は接続カード内を縦にスクロールし、最新版APKが導入されているか`install`を再実行してください。

## 6. デバッグモードへ切り替える

debug APKは初回のみデバッグモードが既定です。現在のモードは次の手順でいつでも切り替えられます。

1. 接続カード右上の「設定」を押す。
2. 「デバッグモード」のスイッチをオンにする。
3. 必要なら解析解像度と最大送信fpsを選ぶ。
4. 「適用」を押す。
5. 画面上部に`DEBUG`、接続カードに「診断」が表示されることを確認する。

本番モードにすると、診断ボタン、疑似入力、検出しきい値を隠し、診断イベントの収集を停止します。撮影、手検出、位置合わせ、PC接続は引き続き利用できます。モードはアプリを終了しても保存されます。

## 7. USB経由でモックPCへ接続する

USB経路はWi-Fi、ルーター、Windows Firewallの影響を受けにくいため、最初の通信確認に適しています。

### ターミナル1: USB経路を設定する

```powershell
.\android\tools\android-debug.ps1 usb -Port 8080
```

次が表示されれば設定完了です。

```text
USB route ready. Android app: host=127.0.0.1 port=8080
```

この操作はUSBを接続し直したときや端末を再起動したときに、もう一度実行します。

### ターミナル2: モックサーバーを起動する

別のPowerShellを開きます。

```powershell
.\android\tools\mock-websocket-server.ps1 `
  -Port 8080 `
  -PairingToken 123456 `
  -InitialMode tracking
```

次のような待受表示を確認します。

```text
YubiBoard mock WebSocket server: 0.0.0.0:8080/ws/v1/input
Pairing token: 123456 / initial mode: tracking / scenario: happy
```

受信が始まると、フレーム番号、検出有無、受信件数に加えて、人差し指先端（ランドマーク8）の`x, y, z`が20フレームごとに表示されます。全21点は表示された結果ディレクトリの`hand-frames.jsonl`へ保存されます。このファイルがPCへ実際に届いた骨格座標の確認用生ログです。

黒背景の骨格動画も同時に作る場合は、サーバーへ`-DurationSeconds 30 -RenderVideo`を追加します。30秒後に自動停止し、同じ結果ディレクトリへ`hand-tracking.mp4`を生成します。Python 3とFFmpegがPATHに必要ですが、追加パッケージは使いません。

```powershell
.\android\tools\mock-websocket-server.ps1 `
  -Port 8080 `
  -PairingToken 123456 `
  -InitialMode tracking `
  -DurationSeconds 30 `
  -RenderVideo
```

すでに取得済みのログは、次のコマンドで後から動画化できます。

```powershell
python .\android\tools\render_hand_video.py `
  .\android\debug-results\server-<日時>\hand-frames.jsonl
```

未検出フレームは黒一色です。検出時は白い線、青い関節、黄色い5本の指先として描画されます。MediaPipeが返した範囲外座標はJSONLでは保持し、動画上だけ画面端へクランプするため、受信値の調査を妨げません。

### Androidアプリで接続する

接続カードへ次を入力します。

| 項目 | 入力値 |
| --- | --- |
| PCのIPまたはホスト名 | `127.0.0.1` |
| ポート | `8080` |
| 6桁コード | `123456` |

「PCへ接続」を押します。

確認する場所は3か所です。

| 場所 | 正常時に見るもの |
| --- | --- |
| Android上部 | `接続中`、`PC応答待ち`を経て`接続済み`になる |
| Android診断 | connection、session、送信数が更新される |
| PCターミナル | `Client connected`と`hand_frame`の受信数が表示される |

接続できない場合は、ホストが`127.0.0.1`であること、両方のポートが`8080`であること、コードが`123456`であることを確認します。

## 8. 手検出を確認する

1. 画面下部が「手の追跡」状態になっていることを確認する。
2. 背面カメラへ片手を向ける。
3. 手をゆっくり動かす。
4. 一度フレーム外へ出し、再び映す。

次を確認します。

| 操作 | Androidで見るもの | PCで見るもの |
| --- | --- | --- |
| 手を映す | 21個の点と骨格線、`手を検出`、fps、推論時間 | `hand_frame`が増える |
| 手を動かす | 骨格が手の移動へ追従する | 連続したフレームを受信する |
| 手を隠す | 未検出または一時喪失へ移る | `detected=false`を受信する |
| 手を戻す | 再び追跡状態になる | `detected=true`へ戻る |

明るさ、背景、カメラとの距離を変え、誤検出や追従遅れがないか確認します。診断画面では、手検出fps、推論時間、人差し指先端、左右分類、送信カウンターを確認します。

## 9. カメラなしで通信だけを確認する

手検出が不安定な場合は、原因をカメラ・検出と通信に切り分けます。

1. デバッグモードを有効にする。
2. PCへ接続済みにする。
3. 「診断」を開く。
4. 「疑似21点」を押す。
5. PC側で手ありの`hand_frame`を確認する。
6. 「疑似未検出」を押す。
7. PC側で手なしの`hand_frame`を確認する。

疑似入力が届くのに実際の手が届かない場合、通信経路は正常で、カメラ権限、映像、MediaPipe検出のどこかに原因があります。疑似入力も届かない場合はWebSocket接続、USB reverse、ポート、コードを確認します。

## 10. 位置合わせを確認する

PCで次の画像を全画面表示します。

```text
android/tools/calibration-target-1920x1080.png
```

画像にはArUco ID 10、11、12、13が次の順に配置されています。

| 位置 | ID |
| --- | ---: |
| 左上 | 10 |
| 右上 | 11 |
| 右下 | 12 |
| 左下 | 13 |

1. Androidの「位置合わせを開始」を押す。
2. PC画面の四隅がすべて背面カメラへ入るようにする。
3. マーカーの黄色い枠とIDが表示されることを確認する。
4. 端末は縦・横どちらでもよいので止め、「安定待ち 1/5」から進捗が増えることを確認する。検出ノイズによる一時的な欠落は2フレームまで許容される。
5. 位置が許容範囲内の有効な5フレームが蓄積され、Androidに「マーカー 4/4・安定」が表示されることを確認する。
6. PC側で`calibration_markers`を受信したことを確認する。
7. 「手の追跡へ戻る」を押し、通常撮影へ戻ることを確認する。

安定判定はマーカー中心のピクセル完全一致を要求しません。黄色いID文字や枠が小刻みに動くのは、フレームごとの検出座標をそのまま描画しているためで、許容範囲内なら進捗は増えます。

| 判定項目 | 現行条件 |
| --- | --- |
| ID | 10、11、12、13の4つがそろう |
| 配置 | ID順に凸四角形を作る。端末の縦横・90度単位の回転は問わない |
| 大きさ | 4中心の正規化面積が`0.01`以上 |
| 揺れ | 各中心が進捗の基準フレームから正規化距離`0.02`以内 |
| 成立 | 条件を満たす有効フレームを5つ蓄積する |
| 一時欠落 | 連続2フレームまでは進捗を保持し、3フレーム連続で不正なら`0/5`へ戻す |

カメラを使わず通信形式だけを確認する場合は、診断画面の「疑似4マーカー」を使います。

## 11. 再接続と障害処理を確認する

### 手動で通信断を再現する

1. 正常接続した状態でモックサーバーのターミナルを`Ctrl+C`で停止する。
   `Client disconnected`の後にPowerShellのプロンプトが戻ることを確認する。ウィンドウの`×`だけで閉じると、子の`pwsh`プロセスが残って8080番ポートを保持することがあるため避ける。
2. Android上部が再接続表示へ変わることを確認する。
3. 1秒、2秒、4秒、8秒、以後10秒の待ち時間で再試行することを確認する。
4. 同じコマンドでモックサーバーを再起動する。
5. Androidが操作なしで`接続済み`へ戻ることを確認する。

`Ctrl+C`後にプロンプトが戻らない、または再起動時に「各ソケット アドレスに対して～1つのみを使用できます」と表示された場合は、8080番ポートを保持するプロセスを確認します。

```powershell
Get-NetTCPConnection -LocalPort 8080 -State Listen |
  Format-Table LocalAddress, LocalPort, OwningProcess
```

行が表示された場合は、`OwningProcess`のPIDを調べます。今回起動したモックの`pwsh`であることを確認できた場合だけ停止してください。

```powershell
Get-Process -Id <OwningProcessのPID>
Stop-Process -Id <OwningProcessのPID>
```

その後、もう一度モックサーバーを起動します。正常に起動すると、待受表示に続いてAndroidからの`Client connected`と`Handshake accepted`が表示されます。

手動停止を使わずに確認したい場合は、最初のモックへ`-DurationSeconds 15`を追加します。15秒後にモック全体が終了してプロンプトへ戻るため、Androidが再接続表示へ変わった後、同じコマンドを再実行して自動復帰を確認できます。

### 用意された障害シナリオを使う

モックサーバーの`-Scenario`を切り替え、1シナリオずつ実行します。

```powershell
.\android\tools\mock-websocket-server.ps1 `
  -Port 8080 `
  -PairingToken 123456 `
  -Scenario mode-switch `
  -DurationSeconds 60
```

| シナリオ | 操作と期待結果 |
| --- | --- |
| `happy` | 通常接続、手データ、heartbeatが継続する |
| `mode-switch` | 約3秒後に撮影モードが遠隔変更される |
| `remote-disconnect` | PC要求で切断状態になる |
| `ack-timeout` | PC応答待ち後、自動再接続へ移る |
| `invalid-json` | 不正JSONを無視し、アプリが落ちない |
| `wrong-session` | 異なるsessionの制御を無視する |
| `schema-mismatch` | 未対応schemaを接続済みにしない |
| `drop` | 通信断後、自動再接続する |
| `slow-reader` | 低速受信でも古いフレームを大量に蓄積しない |

各実行結果は`android/debug-results/server-日時/`へ保存されます。

- `events.jsonl`: 受信イベント
- `connections.csv`: 接続別の受信数、バイト数、検証エラー
- `summary.md`: シナリオ全体の要約

`connections.csv`の検証エラーが0であることを確認します。

## 12. 同一LAN接続を確認する

USB接続で成功した後に実施します。PCとAndroidを同じWi-Fiへ接続してください。

```powershell
.\android\tools\android-debug.ps1 lan -Port 8080
```

表示された候補から、Wi-FiやEthernetのプライベートIPv4アドレスを選びます。モックサーバーはUSB時と同じように起動します。

Android側のホストだけを次のように変更します。

| 項目 | 入力例 |
| --- | --- |
| ホスト | `192.168.1.20` |
| ポート | `8080` |
| 6桁コード | `123456` |

Windows FirewallではTCP 8080の受信を「プライベートネットワーク」に限定して許可します。公衆ネットワークやインターネットへ公開しないでください。

LANで失敗しUSBで成功する場合、アプリではなくPCのIP選択、Wi-Fi分離、Windows Firewallのいずれかが原因です。

## 13. 自動テストを実機で実行する

端末をロック解除したまま、次を実行します。

```powershell
.\android\tools\android-debug.ps1 test
```

このコマンドは次を行います。

1. debug APKをビルドして導入する
2. Compose UIテストAPKをビルドして導入する
3. OpenCVとMediaPipeモデルの同梱を確認する
4. 診断イベントを確認する
5. 「PCへ接続」と設定内の「デバッグモード」が表示されることを確認する

最後に`OK`とテスト件数が表示されれば成功です。

## 14. 10分間の連続動作試験

先にアプリでデバッグモードを有効にし、手の追跡とPC接続を開始します。その状態で実行します。

```powershell
.\android\tools\android-debug.ps1 soak -DurationMinutes 10
```

試験中は次の操作を混ぜます。

1. 手を映して1分程度動かす。
2. 手を隠して再び映す。
3. 位置合わせへ切り替えて4マーカーを検出する。
4. 手の追跡へ戻る。
5. モックサーバーを一度停止して再起動する。
6. 残り時間は手検出と送信を継続する。

結果は`android/debug-results/device-日時/`へ保存されます。

| ファイル | 確認内容 |
| --- | --- |
| `summary.md` | 温度、メモリ、fps、推論時間、送信遅延、crash/ANR数 |
| `device-metrics.csv` | 5秒間隔の温度、メモリ、CPU |
| `logcat.txt` | 診断イベントとAndroidRuntimeエラー |
| `meminfo-final.txt` | 終了時メモリ |
| `gfxinfo-final.txt` | 描画性能 |
| `thermal-final.txt` | 温度制御状態 |

最低限の合格目安です。

- crash/ANRが0件
- 640×480設定で手検出が概ね15 fps以上
- メモリが時間とともに増え続けない
- 端末が熱くなってもアプリが停止しない
- 通信断後に自動復帰する

## 15. 診断ログを保存する

1. アプリをデバッグモードにする。
2. 「診断」を開く。
3. 必要な操作を再現する。
4. 「更新」を押して最新値を確認する。
5. 「JSONL保存」を押す。
6. Androidのファイル選択画面で保存先を選ぶ。

問題報告には、次を一緒に残すと原因を追いやすくなります。

- 再現手順
- 期待した動作と実際の動作
- 端末名とAndroidバージョン
- USB接続かLAN接続か
- 診断JSONL
- モックサーバーの`events.jsonl`、`connections.csv`、`summary.md`
- soak試験を行った場合は`device-日時/`一式

## 16. よくある問題

### `INSTALL_FAILED_USER_RESTRICTED`

Xiaomiなどで端末側がAPK導入を拒否しています。

1. 端末をロック解除する。
2. 開発者向けオプションの「USB経由のインストール」を有効にする。
3. USBデバッグのセキュリティ設定があれば有効にする。
4. コマンドを再実行する。
5. 端末に表示される確認を許可する。

アプリ本体とテストAPKは別々に確認が出ることがあります。

### `ADB接続済み実機がありません`

- USBケーブルを交換する
- 充電専用ではなくデータ通信対応ケーブルを使う
- USB接続用途を「ファイル転送」にする
- USBデバッグの許可を取り消し、接続し直して再許可する
- `doctor`を再実行する

### 複数端末が接続されている

`doctor`で確認したserialを指定します。

```powershell
.\android\tools\android-debug.ps1 doctor -Serial 2bd82477
.\android\tools\android-debug.ps1 install -Serial 2bd82477
```

### 接続ボタンを押しても`接続済み`にならない

- モックサーバーが起動中か
- USB接続では先に`usb -Port 8080`を実行したか
- ホストが`127.0.0.1`か
- ポートが両方とも`8080`か
- 6桁コードが両方とも`123456`か
- 古いモックサーバーが同じポートを使用していないか

### カメラは映るが手を検出しない

- 片手だけを映す
- 指全体がフレームへ入る距離にする
- 手のひら側と手の甲側を試す
- 背景と手の色が分かれる場所に移動する
- 明るさを上げる
- 設定を640×480へ戻す
- 疑似21点で通信だけは正常か切り分ける

### マーカーが4つそろわない

- 画像全体を画面へ表示する
- PC画面とカメラの角度を正面に近づける
- 反射やモアレを減らす
- 4隅をすべてフレームへ入れる
- ID 10、11、12、13が正しい位置にあるか確認する

### マーカーは`4/4`だが「安定」にならない

- まず「安定待ち n/5」の`n`を見る。`1/5`以上へ進むならピクセルの小刻みな揺れは正常
- `0/5`のままなら最新版debug APKを再インストールする
- ターゲットをカメラ内で少し大きく映す。4中心の四角形が画像面積の約1%以上必要
- ターゲット画像を反転・入れ替えせず、ID 10→11→12→13が外周を同じ向きに並ぶ状態にする
- 端末を縦横に回転すること自体は問題ない。手ぶれが大きい場合だけ端末を固定する
- 3フレーム以上連続してIDが欠ける場合は、反射、モアレ、ピント、画面輝度を調整する
- 安定後はPC側の`calibration_markers`件数が増えることも確認する
