**今ある画面を買い替えず、「操作できる」を後付けする。**

Screactは、**タッチ機能のない普通の画面を、手でそのまま操作できるようにするシステム**です。

画面の横にスマホを置き、そのカメラを画面の「目」にします。スマホが手指の動きと画面の位置を認識してPCへ送り、PCがそれをクリック・ドラッグ・スクロール・書き込みに変えます。今あるモニターやプロジェクターを買い替えずに、「操作できる」を後付けします。

## <a id="製品概要"></a>PART 1 製品概要（PRODUCT）

### <a id="背景"></a>01 背景（製品開発のきっかけ）

Screactの出発点は、「プレゼンのとき、画面の前でそのまま操作できたらいいのに」という思いつきでした。説明する人は画面の前にいるのに、スライドを送ったり書き込んだりするたびに、PCの前へ戻らなければなりません。

普通のモニターとマウスでも、説明や会議は成り立ちます。それでも、画面を指し示しながら、その場で書き込み、動かせたら、話はもっと伝わり、もっと一緒に考えられるはずです。画面を直接操作する体験を、特別な機器がなくても、身の回りのどの画面でも味わえるようにしたいと考えました。

**情報を映す画面から、情報と関わる画面へ**

- 普通のモニターやマウスでも、説明や会議は成り立ちます。Screactは、そこに「画面を直接さわって動かす」体験を足し、指し示す・書き込む・動かすを、話しながらその場でできるようにします。

### <a id="製品説明"></a>02 製品説明（具体的な製品の説明）

**今ある画面 × スマホ：普通の Screen が、人の動きに React する。**

スマホを画面の横に立てて置き、スマホとPCのアプリでそれぞれボタンを1つ押すだけで準備が整います。スマホがPCを見つけて自動でつながり、画面の四隅に出たマーカーを読んで位置を合わせます。あとは画面の前で手を動かすだけです。

**製品の仕組み**

- STEP 1：スマホが「見る」。画面の横に置いたスマホのカメラが、手指の21点と画面の四隅を、端末の中で認識します。
- STEP 2：PCへ「送る」。カメラの映像ではなく、座標と状態だけを、同じLANのPCへリアルタイムに送ります。
- STEP 3：画面が「応える」。PCが座標を画面に合わせ、手の形を操作に変えて、いつものアプリを動かします。

**実際の画面**

- PC：位置合わせ（画面の四隅にArUcoマーカーを出す）。
- スマホ：手の追跡（手指の21点を追い、座標と状態を送る）。

接続から操作までの、PCとスマホのすべての画面は[ギャラリー](docs/gallery.md)で見られます。名前の **Screact** は、Screen と React を合わせた言葉です。

### <a id="できること"></a>03 できること

手の形を読み取り、PCの基本の操作に変えます。描いた線は透明なオーバーレイに重なり、クリックやスクロールはOSの実際の入力として届くので、ブラウザ・スライド・PDFなど、いつものアプリをそのまま動かせます。

**できること**

- 描く・消す：描くは人差し指と中指をくっつけて動かす、消すは手をグーにして動かす（透明なオーバーレイに描くので、ブラウザやスライドを隠しません）。
- クリック・選択：親指と人差し指をつまむ（OSの実際のクリックとして、いつものアプリに届きます）。
- 掴む（ドラッグ）：つまんだまま動かす（ファイルや付箋、ウィンドウを、つまんで運びます）。
- スクロール：グッドサイン（親指だけを立てる）（親指を向けた方向へ、縦にも横にもスクロールします）。
- ポインター：人差し指を動かすと動く。
- 設定：各操作は設定画面で1つずつ有効・無効を切り替えられる。

手を見失ったときや通信が切れたときは、押している途中・描いている途中の状態を自動で解除します。描く色、骨格の表示、認識の感度は、PCの設定画面で変えられます。

### <a id="特長"></a>04 特長

画面を直接さわって動かす体験は、電子黒板やタッチディスプレイでも得られます。ただ、それには画面の買い替えが必要で、お金も時間もかかります。Screactは、今ある画面に「操作できる」を後付けします。

**特長**

- 1：今ある画面を、そのまま使う。教室・会議室・店舗にあるモニターやプロジェクターを、買い替えずに使います。タッチ対応の画面へ入れ替える必要はありません。
- 2：専用の機器がいらない。赤外線カメラやセンサー、電子ペンは使いません。誰もが持っているスマホとPCに、アプリを入れるだけで始められます。
- 3：いつでも、どこでも。スマホを持ち運べば、その場の画面が操作できる画面になります。スマホは斜めに置いても位置を合わせられます。

**専用の機器を入れる場合との比べ**

- 画面：専用の機器はタッチ対応の画面へ買い替える、Screactは今あるモニター・プロジェクターを使う。
- 追加の機器：専用の機器は赤外線カメラ・センサー・電子ペンなど、Screactはいらない（手元のスマホとPCだけ）。
- 導入：専用の機器は設置の工事や設定、Screactはアプリを入れるだけ。
- 場所：専用の機器は設置した場所に固定、Screactはスマホを持ち運べば、どこでも。

### <a id="利用場面"></a>05 利用場面

モニターは、教室にも、会議室にも、店舗にもあります。直接操作できる画面は、人と情報、人と人の関わり方を変えます。

**利用場面**

- 会議・共同作業：情報を動かしながら、一緒に考える。注目している箇所や意図を、その場で共有できます。画面を囲んだ全員が、対話や共同作業に加わりやすくなります。
- 授業・プレゼン：説明・身振り・操作がひとつになる。説明する人は画面の前から離れず、伝えることに集中できます。聞く人も、どこを見ればよいかをつかみやすくなります。
- 接客・相談・提案：同じ情報を指しながら対話する。相手の反応や質問に合わせて、その場で書き込みながら説明できます。

### <a id="直接操作の価値"></a>06 直接操作の価値

画面を直接操作することの価値は、これまでの研究でも報告されています。直接操作は、操作しやすいだけでなく、操作の意図が周りに伝わりやすくなります。

**直接操作の価値（先行研究）**

- 高齢者の操作時間がマウスより約35%短い（タッチスクリーンとマウスの比較 [1]）。若年者の操作時間がマウスより約16%短い（タッチスクリーンとマウスの比較 [1]）。両手を使う作業では直接タッチが有利（テーブル型ディスプレイでの比較 [2]）。
- 注意：先行研究の結果であり、Screact自体で測った効果ではありません。

タッチスクリーンで商品を見たときには、「自分のもの」という感覚が最も強くなり、商品をより高く評価する傾向も報告されています [3]。

> [!NOTE]
> ここで紹介しているのは、一般的な直接操作（タッチスクリーンなど）に関する先行研究の結果です。Screact自体で測った効果ではありません。出典は[参考文献](#参考文献)にあります。

### <a id="注力したこと"></a>07 注力したこと（こだわり等）

「手を認識できる」だけでは、画面は操作できません。画面のどこを指しているのか、指先の揺れをどう抑えるか、何をしたいのかをどう読み取るか、どうやってアプリに届けるか。認識から操作までを一つの体験としてつなぐために、4つの点に注力しました。

**注力したこと**

- 1：導入の手軽さ（ユーザー操作は最小限）。PCがUDPで居場所を知らせ、スマホが見つけて自動で接続します。位置合わせも、画面の四隅のマーカーを読むだけで終わります。
- 2：設置の自由度（スマホは斜めからでもOK）。4つのマーカーからホモグラフィ（射影変換）を求め、斜めから見た座標を画面の座標へ補正します。説明者や聞き手の邪魔になりません。
- 3：操作性（直感的なジェスチャーと滑らかさ）。止めていても揺れる指先を、One-Euro Filterで落ち着かせつつ、動き出しの速さは保ちます。判定は行き来の幅を持たせ、線の途切れを防ぎます。
- 4：汎用性（実カーソル入力で、どのアプリでも）。OSの実際の入力としてクリック・ドラッグ・スクロールを送ります。描画はクリック透過のオーバーレイに重ね、普段のアプリをそのまま使えます。

### <a id="今後の展望"></a>08 今後の展望

**今後の展望**

- まず：使い続けられる品質へ。通信環境によるカクつきや、意図しない描画を減らします。描き直しのためのUndoや、長い時間使っても安定することを確かめます。
- その先：場面に合わせた操作へ。スライドごとに書き込みを残すプレゼンモードや、用途ごとのジェスチャーの組み合わせを、実際に使ってもらいながら形にします。

## <a id="開発技術"></a>PART 2 開発技術（TECHNOLOGY）

### <a id="システム構成"></a>09 システム構成

スマホは「見る」役、PCは「操作に変える」役です。カメラの映像はPCへ送らず、スマホの中で認識した座標と状態だけを送ります。通信量を抑えられ、操作の判定はPC側でまとめて調整できます。

**システム構成**

- スマホ（Android：Kotlin・Jetpack Compose・CameraX／iOS：SwiftUI・AVFoundation、実験的）が、MediaPipe Hand Landmarker で手指21点を、OpenCV ArUco で画面四隅のマーカーを端末の中で認識する。PC（Flutter Desktop）は UDP 8766 で接続情報を広告し、スマホは WebSocket 8765（/ws/v1/input）で座標と状態だけを送る。PCは Homography で画面座標へ変換し、One-Euro Filter で揺れを抑え、ジェスチャーを判定して、透明・クリック透過のオーバーレイへの描画と、OSの実入力（macOS：CGEvent、Windows：SendInput）に変える。それがブラウザ・スライド・PDFなどの既存のアプリに届く。流れる点は、手の動きが画面に届くまでの道。

| 通信 | 既定値 | 役割 |
|:--|--:|:--|
| UDP | `8766` | PCの居場所、WebSocketのポート、6桁コードをスマホへ知らせる（自動発見専用） |
| WebSocket over TCP | `8765` / `/ws/v1/input` | 認証、位置合わせ、手指21点、状態、制御のメッセージ |

手指のデータはUDPでは送りません。メッセージの形式は[通信仕様書 v1](docs/protocol-specification-v1.md)を正本にしています。

### <a id="活用した技術"></a>10 活用した技術

**活用した技術**

- Android（android/・Kotlin）：Kotlin・Jetpack Compose（状態ごとのガイド、接続、設定の画面）、CameraX（背面カメラ・古いフレームは捨てる（KEEP_ONLY_LATEST））、OkHttp WebSocket・UDP（PCの自動発見と、リアルタイムの送信）、Android Keystore（信頼済みの再接続に使うトークンを AES/GCM で保護）。
- 認識（スマホの中で完結）：MediaPipe Hand Landmarker（手指21点・既定は1手、設定で最大2手）、OpenCV ArUco（DICT_4X4_50 の四隅マーカー・ID 10〜13）、解像度のフォールバック（1280×720 → 960×540 → 640×480）。
- Desktop（desktop/・Flutter）：Flutter・Dart（接続・位置合わせ・オーバーレイ・設定の4画面）、Homography（4点のマーカーから、カメラ座標を画面座標へ）、One-Euro Filter（静止時の揺れを抑え、動き出しの応答は保つ）、ジェスチャー判定（手の大きさで正規化したしきい値と、ヒステリシス）。
- OSとの連携（ネイティブ）：macOS：Swift・CGEvent（ポインター・クリック・ドラッグ・スクロール）、Windows：C++・Win32・SendInput（実マウス入力と、透明・最前面・クリック透過のウィンドウ）、ショートカット（オーバーレイの解除 ⌘⇧O／Ctrl+Shift+O）。
- 通信（同じLANの中で完結）：UDP :8766（PCの居場所・ポート・6桁コードの広告（自動発見専用））、WebSocket :8765（/ws/v1/input で、認証・位置合わせ・手指21点・状態）、自動再接続（1・2・4・8秒、以後10秒ごとに再試行、ネットワークが戻ればすぐ再接続）。
- iOS（実験的）（ios/・SwiftUI）：SwiftUI・AVFoundation（Androidと同じ通信の契約で動くクライアント）、NWConnection（RFC 6455 の WebSocket を生のTCPの上に実装）、Bonjour（iPhone ↔ macOS の自動接続を実機で確認）。

### <a id="クイックスタート"></a>11 クイックスタート

**必要なもの**

- Android 7.0（API 24）以上のスマホ（背面カメラ）
- macOS 10.15以上、またはWindowsのPC
- スマホとPCが互いに通信できる、同じLAN（Wi-Fi）
- 開発環境：Flutter（Dart SDK `^3.7.2`）、Android Studio（Android SDK 36、JDK 17）。macOSはフル版のXcode、WindowsはVisual Studioの「Desktop development with C++」

**1. PCのアプリを起動する**

```bash
cd desktop
flutter pub get
flutter run -d macos     # Windows では -d windows
```

macOSでは、初めて接続するときにローカルネットワークへのアクセスを許可してください。クリックやスクロールを使うには、「システム設定」→「プライバシーとセキュリティ」→「アクセシビリティ」でScreactを許可します。

**2. スマホのアプリを入れる**

```bash
cd android
./gradlew assembleDebug          # Windows では .\gradlew.bat assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Android Studioで開くときは、リポジトリ全体ではなく `android/` を開いてください。iOS版（実験的）は[ios/README.md](ios/README.md)を参照してください。

**3. つないで、合わせて、操作する**

1. PCの画面全体と手が映る位置に、スマホを固定する（斜めからでも構いません）
2. スマホでScreactを起動し、「画面認識開始」を押す
3. PCでScreactを起動し、「はじめる」を押す（スマホがPCを見つけて、自動でつながります）
4. つながると、PCの画面の四隅にマーカーが出て、スマホが読み取って位置を合わせます
5. 位置合わせが終わると、透明なオーバーレイに切り替わります。手で操作を始めてください

自動でつながらないときは、スマホの「手動で接続する（IP・6桁コード）」から、PCの画面に出ているIP・ポート・6桁コードを入力してください。オーバーレイの解除は、macOSではメニューバーの鉛筆のアイコンか `⌘⇧O`、Windowsでは `Ctrl+Shift+O` です。

<details>
<summary><b>対応状況と既知の制約</b></summary>

| 対象 | 状態 |
|:--|:--|
| Android + macOS | 主な経路。発表と展示で使用 |
| Android + Windows | 透明オーバーレイと、SendInputによるネイティブ入力を実装。特定の環境の実機で確認済み |
| iOS | 実験段階。iPhoneとmacOSの自動接続は実機で確認済み。手とマーカーの認識にはCocoaPodsの導入が必要 |

- 自動発見はUDPのブロードキャストを使うため、VPN、ゲストWi-Fi、AP isolation、ファイアウォールなどの環境では失敗することがあります。そのときは手動接続を使ってください。
- PCが同時に受け付けるスマホは1台です。
- 位置合わせの結果は、PCのアプリを終了すると消えます。
- 通信は、信頼できる同じLANでの利用を前提とした、暗号化なしのWebSocketです。
- 単眼のカメラなので、画面に指が触れた瞬間は検出しません。つまむなどのジェスチャーで、操作の意思を表します。
- 手による拡大・縮小のジェスチャーは、まだありません。

</details>
